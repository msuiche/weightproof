# M1 integer reference model

Status: normative semantics for the dense GPT-2-class CPU milestone. This is the
computation to be proved; it is not an approximation contract for a different
forward pass. Source of the equations: `spikes/flashprove/docs/model.md`.

## 1. Values and operators

Every quantity is an unbounded integer. Array indices start at 0.

- `rq(a, k) = floor((a + 2^(k-1)) / 2^k)`, for `k >= 1`: divide by `2^k`, round to
  nearest with ties upward.
- `clamp(a; b) = min(max(a, -b), b)`.
- `isqrt(a)` is the largest integer `r` such that `r^2 <= a`.
- `argmax` returns the least index at which the maximum is attained.
- `low8(a) = ((a + 128) mod 256) - 128`.
- `floor` rounds toward minus infinity; `a mod b` is in `0 .. b - 1`.
- A matrix `W` has the input index first: `(x W)[j] = sum_k x[k] W[k][j]`.
- A stream activation is clamped to 12 signed bits: `clamp(x; 2047)`.

The model has no bias vectors and no norm gains. Gains are folded into the
committed matrices and scales.

## 2. Public shape and weights

The statement binds `L`, `d`, `dh`, `f`, `H`, `G`, `T`, `V`, `cs`, `theta0`,
`expS`, `rx`, `eg`, `smax`, and all shifts and norm regularizers. `H` is the
number of query heads and `G` the number of key-value heads; `dq = H dh` and
`dkv = G dh`. `NE = 0` for M1: every layer is dense.

Committed matrices are:

- `Wq: d x dq`, `Wk: d x dkv`, `Wv: d x dkv`, `Wo: dq x d`;
- `Wg: d x f`, `Wu: d x f`, `Wd: f x d`;
- `Emb: V x d`, `Wh: d x V`.

`KL.bin` supplies per-layer `kq`, `kk`, `kv`, `ko`, `kg`, `ku`, `kd`, norm
exponents `M1`, `K1`, `M2`, `K2`, softmax shift `sh`, and rotary-enable `rp`.
The final norm supplies `MF`, `KF`, and `epsF`. Every shift and every `eps` is at
least 1. `eps1` and `eps2` are per-layer values.

Weights and parameters are part of the statement, not implementation details. A
parameter-file or model-revision mismatch is a different computation and MUST be
rejected.

## 3. Public nonlinear tables

Tables are generated by the specified float64 sequence, with one rounding per
operation, then converted to integers. No fused or reordered evaluation is
allowed.

- Rotary: `C(t,i) = rha(2^cs cos(t theta0^(-2i/dh)))` and
  `S(t,i) = rha(2^cs sin(t theta0^(-2i/dh)))`, with `rha` rounding ties away
  from zero.
- Softmax: `EX[u] = rne(2^expS exp(-u / 2^rx))`, with `rne` rounding ties to
  even. The table ends before the first zero entry.
- SiLU: `Ts[c] = clamp(rha(64 * (z / (1 + exp(-z)))); smax)`, where
  `z = min(max(c, -64 * 2^eg), 64 * 2^eg - 1) / 2^eg`.
- Sigmoid: `Sig[c] = 16 * rha(4096 / (1 + exp(-c / 256)))`.

The statement includes the digests `tsilu`, `tsig`, `trope`, and `texp`. A
library or table whose digest differs MUST fail closed. Correctly rounded table
entries are part of the statement; using a platform's unverified math library
without checking the digest is not accepted.

## 4. Norm

For a row `x` of `d` stream values:

```
Vx    = sum_k x[k]^2
sigma = isqrt(Vx + eps)
Rc    = floor((2^M + floor(sigma / 2)) / sigma)
w[k]  = rq(x[k] Rc, K)
N(x; M, K, eps)[k] = clamp(w[k]; 2047)
```

`Vx` may exceed 64 bits. The factor `sqrt(d)` is folded into weights/scales, not
inserted as a separate runtime gain.

## 5. Layer

For input row `x_t`, with the layer's scales:

1. `a_t = N(x_t; M1, K1, eps1)`.
2. Compute `a_t Wq` and `a_t Wk`. For each head and pair `(A0,A1)`:
   - if `rp = 1`, use rotary `C = C(t,i)`, `S = S(t,i)`;
   - otherwise use `C = 2^cs`, `S = 0`.
   - `p0 = C A0 - S A1`, `p1 = S A0 + C A1`.
   - `q = clamp(rq(p, kq); 2047)` for queries, `k = clamp(rq(p, kk); 2047)` for
     keys.
3. `v = clamp(rq(a_t Wv, kv); 2047)`.
4. Query head `h` uses key-value head `g = floor(h / (H / G))`. For `j <= i`:

   ```
   s_ij = sum_c q_i[h][c] k_j[g][c]
   m_i  = max_j s_ij
   u_ij = floor((m_i - s_ij) / 2^sh)
   e_ij = EX[u_ij] if u_ij < u0, else 0
   Z_i  = sum_j e_ij
   acc_i[c] = sum_j e_ij v_j[g][c]
   o_i[h][c] = floor((2 acc_i[c] + Z_i) / (2 Z_i))
   ```

   `Z_i > 0` because the largest score has `u = 0`.
5. `ad = rq(o_t Wo, ko)` and `x'_t = x_t + ad`.

The `1/sqrt(dh)` attention scale is folded into `Wq`. No query/key normalization
or long-context attention is included in M1.

## 6. Dense feed-forward

Let `m = N(x'_t; M2, K2, eps2)`. For each hidden unit `j < f`:

```
gw  = rq((m Wg)[j], kg)
g0  = low8(gw)
gh  = (gw - g0) / 256
gc  = clamp(gh; 127)
key = 256 gc + g0
s   = Ts[key]
u   = rq((m Wu)[j], ku)
ad  = rq(sum_j s[j] u[j] Wd[j][k], kd)
x'' = x' + ad
```

The SiLU table is constant when `gc` saturates; clamping does not create a new
nonlinearity.

## 7. Embedding, final norm, and output

For token ids `tok_0 .. tok_(T-1)` below `V`:

```
x^0_t = Emb[tok_t]
x^(l+1) = layer_l(x^l), for l < L
aF_t = N(x^L_t; MF, KF, epsF)
lam_t = aF_t Wh
y = argmax(lam_(T-1))
```

The first argmax wins ties. Padding is part of the statement and follows the same
computation. A proof covers a stated token range; it does not automatically cover
every position.

## 8. Domain and range conditions

The model is defined only when the public range conditions hold. They are not
optional validation hints. A prover MUST NOT produce a proof outside the domain,
and a verifier MUST reject any claimed satisfaction outside it.

| Value | Defined range |
|---|---|
| `Vx + eps` | `< 2^78` |
| Norm quotient `w[k]` | `-32768 .. 32767` |
| Wide query/key `qw`, `kw` | `-32768 .. 32767` |
| Wide value `vw` | `-32768 .. 32767` |
| Gate high part `gh` | `-16384 .. 16383` |
| Up projection `u` | `-32768 .. 32767` |
| Stream `x[k]` | `|x[k]| < 2^39` |

The prover's narrower accepted intervals end at `32639` and at `547599908735` for
`x[k]`; these are implementation limits, not widened model semantics. A value
between the model boundary and the prover boundary is defined but unprovable by
that prover. `K > M` is outside the standard parameter form. Norms must have
`24 <= M <= 47`, `17 <= K <= 32`, and `K >= M - 14`.

M1 has no routed-expert condition because `NE = 0`.

## 9. Statement serialization

For M1, each public table is encoded independently as a `u64` element count
followed by signed 64-bit little-endian entries. The table order is
`cos, sin, EX, Ts, Sig`; table regions are contiguous and their byte offsets and
lengths are public. Independently, the statement's `trope`, `texp`, `tsilu`, and
`tsig` digests use FlashProve's unkeyed BLAKE2b-512 public-table construction:
little-endian `u32` entries, compression counter high half `72 + 2^32 n`, and the
first 32 output bytes. Their word streams are rotary `C + 4096` then `S + 4096`,
all `EX`, all `Ts + 4096`, and the readable sigmoid half followed by
`clamp(r; 127) + 128`. The statement also carries `u0`. The CPU prover must use
the serialized table bytes when constructing lookup commitments.

Weight matrices use `u64 rows`, `u64 columns`, then signed 64-bit little-endian
entries in row-major order. The weight commitment covers embedding, then
`wq,wk,wv,wo,wg,wu,wd` for each layer, then the output head. The execution
commitment covers tokens, every post-block residual matrix, and the output token
in that order. `BlockStatement` binds both commitments, the table digests, final
norm parameters, and the claimed output; `verify_block` recomputes all of them.

For field commitments, signed values use little-endian balanced base-256 limbs
in `-128..=127`, mapped into Goldilocks. Embeddings use four limbs, other weight
matrices use two, and residual entries use five. Five limbs represent at most
`547599908735` on the positive side, exactly the prover's residual limit; a
failed exact decomposition is not a valid encoding.

`protocol_inputs` maps arithmetic rows to dense multilinear tensors, zero-padded
to a power of two, and maps each public table to a `ForestInput`. Lookup tables
use last-entry padding to the protocol's minimum depth of 10. These are inputs
to the existing arithmetic and lookup protocols, not a separate commitment
scheme. `BlockStatement` also commits to the canonical field rows in fixed
weight/residual/lookup order. Each lookup table has an executable `LkpPublic`
representation; `lkp_row` must return the encoded table value at every claimed
key.

The statement separately commits to model dimensions, every quantization shift,
rotary flags, and all norm epsilons. `canonical_bytes` encodes every public
digest and output parameter for the M1 Fiat–Shamir chain. `ProverTr` writes
canonical extension-field messages and derives challenges with the exact
verifier schedule. `prove_psc_product` emits a complete product-relation PSC
transcript; `psc_verify` accepts the honest transcript and rejects a mutated
round polynomial through a nonzero residual or an error. `PscRoundProver`
generalizes emission to witness-supplied round polynomials, checked against the
running sum and final relation. `psc_prove_begin`, `psc_prove_round`, and
`psc_prove_ends` expose the forest-shaped composition and reproduce the verified
product transcript byte for byte. Slot-aware variants hide endpoint values in
`HFork` and construct affine rows. All 31 initial forest PSC sequences have
executed with concrete witnesses and zero residual rows. `prove_product_level`
emits caller-supplied level polynomials and line challenges, `prove_forest_leaves`
drives the final evaluation-point rounds, and `prove_forest_bit_row` enforces
`bit * bit - bit = 0` through the same transcript schedule. `prove_forest`
integrates every stage, records the scalar layout, evaluates nonzero public
tables, and checks slot counts. `forest_pad` consumes generated transcripts and
reproduces zero-residual rows. `BlockProof` binds the SiLU forest to
`BlockStatement`; `verify_block_forest` rejects statement mutations. Nonzero
`pub_counts` are supported and bound through the forest accumulator. Execution
traces record every gate `(s,u)` witness; the first gate emits a PSC product
proof before the forest, and verification continues the same chain across both
stages. Every gate and every query-key/exponential-value product now has a PSC
proof on that chain. Matrix projections, rotary pairs, norm squares/quotients,
and the output head are included, while each residual addition uses the linear
PSC relation `x + ad * r`. All recorded forward arithmetic witnesses are covered.
Execution traces also record every SiLU and softmax key/value. One combined
forest covers both tables with per-tree counts derived from those reads; the
fixture binds two SiLU and six softmax reads in 66 rows. Arithmetic-byte,
lookup-count, individual lookup-key, individual lookup-value,
execution-commitment, and output mutations are rejected; restoration verifies
again. Tree counts are computed from table depths. The upstream Python/Lean
dense model also generates and verifies a complete block proof: output token 48,
28,552 arithmetic proofs, 66 rows, and 8 SiLU plus 128 softmax reads. A
two-layer fixture verifies with four SiLU and twelve softmax reads, and two
independent token requests verify separately with distinct token commitments;
using the wrong request fails closed. `prove_block_batch` and
`verify_block_batch` expose the independent-request API. Large lookup counts
are split across duplicate public-table trees with at most 4,095 reads per tree.
Two upstream eight-token requests verify with outputs 48 and 6, 683,360
arithmetic proofs each, 67 forest rows, and 64 SiLU plus 4,608 softmax reads;
cross-request verification fails. Product witnesses are batched into dot-product
sumchecks over 64 pairs, reducing that request to 10,930 arithmetic proofs while
preserving every committed pair and all mutation checks. Residual additions are
also folded into one linear PSC relation, leaving 10,675 arithmetic proofs per
request. The two-request transcript totals 67,685,664 bytes, dominated by
24-byte extension-field endpoint values. Arithmetic endpoints now use 8-byte
base-field encoding, expanded to full coordinates during verification without
changing the Fiat–Shamir chain. Forest messages remain 24-byte scalars. This
reduces the same transcript to 23,967,008 bytes with identical verification.
`BlockStatement.format_version = 1` selects this encoding. Verification rejects
other versions, zero or out-of-range offsets, unsorted offsets, truncation, and
non-canonical field values. The `fp_compact_proof` libFuzzer target mutates real
proofs, offsets, and versions and asserts crash-free rejection. CI runs it with
the existing parser targets; the local run completed 1,583 cases without a panic.
All five targets now run in CI and locally. `fp_layout` was restored

## 10. M2 performance baseline

`cargo bench --bench block_proof` measures the complete small-model block proof
and independent verification in release mode. The multilinear Rust baseline is
**2.94 ms proving** and **3.11 ms verification**. ICICLE CPU takes **9.02 ms**
and **6.26 ms** after pairing both witness vectors into one fold per round;
unpaired folds took 14.73 ms and 9.26 ms. Native CUDA on the GB10 takes
**5.82 ms proving** and **5.73 ms verification** with operation-specific
mapped/copy transfer paths and persistent per-thread buffers, down from 7.78 ms
and 5.80 ms with copies alone. The scaled fixture takes 21.98 ms/17.20 ms
(prove/verify) over 30 samples. The earlier 7.78/5.80 ms and 21.80/15.95 ms
baselines used per-fold copy calls for every operation. CI runs the same benchmark with a short
sample, including two-layer and two-request cases.

## 11. M2 kernel lane

ICICLE v4 (`625532a6`) is the CPU arithmetic backend and remains opt-in through
`icicle-prover`, leaving default and no-std verifier builds independent. Its CUDA
source backend is unavailable and its release binaries target x86, so GPU proving
uses the fixed `cuda/fold.cu` kernel through a small C ABI instead. The
`native-cuda` feature builds that kernel with NVCC and confines unsafe Rust to
`fp::native_cuda`; no `cudarc` or ICICLE CUDA installation is required.
`fp::gpu::sumcheck_fold` computes
`out[i] = a[2i] + r * (a[2i+1] - a[2i])` on the selected backend while weightproof
retains ownership of the statement and transcript.

The 1,024-element differential test matches the existing Rust field arithmetic
on ICICLE CPU and rejects odd input and incorrect output lengths.
`sumcheck_fold_extension` additionally implements the protocol's actual cubic
extension arithmetic, including the `X^3 = 2` reduction, and matches the existing
Rust extension implementation on 256 nontrivial elements. The `gpu_kernel`
benchmark compares Rust with the active backend from 1,024 through 262,144
elements. Fusing the cubic
program and performing the even/odd split during host conversion reduced the
1,024-element ICICLE CPU fold from 22.26 ms to 340 us (about 65x). Plain Rust
takes 3.53 us at this small size, so this is a correctness and dispatch baseline,
not a claim that ICICLE CPU is faster. `DotProductRoundProver` now emits real
quadratic multilinear rounds with epsilon scaling, folds both witness vectors
after every challenge, and zero-pads non-power-of-two witnesses. With
`icicle-prover` enabled, those rounds and `fold_low_once` use the verified kernel;
`Tensor::folded_dense` covers the strided variant. The accepted key verifier also
exercises the proximity path. All 133 ICICLE-enabled tests pass, including
statement mutations and explicit multilinear/padding assertions. A default-vs-
ICICLE smoke run produced byte-identical multilinear block proofs with SHA-256
`04d95d7500f779145f1018a711496f318d1baa257b5ebada780640a0ea92c7ea`.
CI runs the complete ICICLE-enabled suite.

`formal/GpuFold.lean` proves universal correctness of the fused equations against
an independent reference fold, the multilinear dot-product quadratic coefficient
identity, and non-vacuity witnesses. It also proves canonical Goldilocks field
operations, exact unsigned-word addition, subtraction, 128-bit reduction, and
multiplication, plus fixed-launch index bounds and active/inactive behavior.
These proofs have no `sorry` or user-added axioms. CI checks this file with Lean
4.34.1. PTX/compiler/hardware semantics remain outside the model.

On `dgx1` (aarch64 Ubuntu 24.04, NVIDIA GB10, NVCC 13.0), all **138** tests pass
with `native-cuda`, including real multilinear block proving and accepted/mutated
request verification. Generic fold chains reuse a per-thread `SeriesContext`;
an 8,192-element, thirteen-challenge chain improved from 208–241 us to
119–130 us. Large dot-product rounds keep witnesses resident: each
fold also computes the next round's coefficients from the folded values. Three
A/B runs for an 8,192-pair proof improved from 2.24/1.74/2.25 ms to
2.09/1.66/2.08 ms with byte-identical proof bytes. Native CUDA and default Rust produce byte-identical
multilinear block proofs with the same SHA-256 above. The standalone CUDA test
also checks 512 outputs at each of ten strides against independent 128-bit host
arithmetic. `make -C cuda check` reproduces the executable and PTX; the generated
kernel targets `sm_121`. Below 8,192 input elements the backend uses Rust;
at and above that measured crossover it uses native CUDA. This reduces the
four-layer/f8/window-8 fixture to 8.68 ms proving and 8.80 ms verification in
interleaved A/B runs. The thresholded proof encoding is byte-identical to the
pre-threshold encoding. PTX-level formalization is reviewed in
`spec/ptx-review.md`; full-model 8B performance is still outstanding.

## 12. Required evidence and M1 acceptance

Before prover optimization, implement and test the exact formulas above against
`integrations/vllm/integer_model/model.py` and the Lean vectors, including:

- ties in `rq`, `argmax`, and rounding tables;
- every range boundary and just-outside value;
- `Z_i = 1`, padded windows, and `K > M` rejection;
- overflow beyond 64 bits and non-canonical field encodings;
- residual, query/key/value, KV-cache, expert-free feed-forward, final norm, and
  output-token equality on the same weights;
- a full transformer block bound to one execution and one weight commitment.

M1 acceptance requires all existing verifier tests to keep passing, exact C++/Rust
agreement on the new dense vectors, and no proof for an out-of-domain or altered
statement. The target verifier limits are at most 60 seconds per request on an
8-core laptop CPU, at most 4 GB RAM, and at most 32 MB proof per 1,024-token
window. Do not scale kernels before this block verifies.
